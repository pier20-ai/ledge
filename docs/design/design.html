D1

Why now — the three defects

DEFECTIcon-only buttons render off center

LedgeButton.layout() centers the group icon + gap(5) + label. With label="" the label still contributes its 5 pt cell pad and the icon still pays the 5 pt gap — 10 pt of phantom content, so the icon lands 5 pt left of center. Every icon-only button in every app is wrong by the same amount: music's transport, chess's controls, anything <button label="" icon="sf:…">.

Material & color

The material is black glass. Ink is one white at four opacities. Hue is spent only on meaning — never on chrome.

Each hue also exists as a tint (fill ≈ .09) and a stroke (≈ .25) pair — apps say fill="greenTint", never a value. Rule of use: at most one hue family per card; accent appears at most once per panel (the primary action). Everything else is ink and glass.

D4

Geometry — spacing, radius, hit targets

Spacing: the 4-pt grid

All gaps and pads from 4 · 8 · 12 · 16 · 20. Stack default gap 8, card pad 12, panel content pad 12 (= the concentric inset). Odd values are a review flag.

Radius: two rules replace nine values

ruleapplies tovalue
Capsule — radius = height/2buttons, icon buttons, inputs, pills, dots, knobs, tracks, the collapsed notch itselfr-pill (34 pt ⇒ 17)
Concentric — child radius = parent radius − inset (floor 4)panel 26 → content 14 → tiles 8; cards 12 → nested chips 8r-panel 26 · r-content 14 · r-card 12 · r-chip 8

This is why the current button "feels off": radius 10 on a 34-pt control is neither capsule (17) nor concentric with anything. The panel got this right on day one; the components never followed. All layer corners get cornerCurve = .continuous (Apple's squircle — the notch cutout itself curves continuously, and r10 next to it reads cheap).

Q1 side by side, live — ruled: capsule (D8). It is the notch's own silhouette, and it makes icon-only buttons perfect circles for free.

Panel wings & the exclusion zone SPEC

The expanded panel's top row — cutout height — is an exclusion zone: the §5 tree mounts below it, so no app can put content behind the camera (nearly every app did). The areas flanking the cutout are the two panel wings: the LEFT wing defaults to the app's name (s/semibold, secondary, ellipsized) and an app may claim it with a <wing side="left"> root child; the RIGHT wing is shell-reserved for the Edit-with-AI affordance — a size-s glass capsule (wand.and.stars + "Edit") that presents the app's chat surface. A right wing from an app is a rejected commit. Zones hard-clamp and ellipsize when the panel nears cutout width — the same discipline as the collapsed wings' RC fix. Distinct concept from §3.3's collapsed wings below.

Wings (collapsed live text)

Cutout-anchored — the shape grows symmetrically off the hardware cutout, never centers on its own width. Text 11 pt medium secondary, ellipsized, hard-clamped so it can never slide behind the camera. Latest-asker-wins; wings release on every lifecycle transition. Canvas wings draw into the same strip at the same height. (All shipping — recorded as law after the RC fix.)

App strip (shell chrome) SPEC

Layout: [scrolling icon area] [+ new-app] [gap ≥ 12] [settings, pinned right]. Icons scroll horizontally (overlay scrollers, no visual change when everything fits); the + and settings never scroll out of reach, and the safe gap before settings survives maximum crowding. Icons stay 34 pt circles, tint-only hover, syncHover verified against the live pointer even mid-scroll (L5).

Canvas

The app's pixels, the shell's frame: canvases sit on a sunken mat with chip radius 8. Upscaled sprites draw with interpolation none (pixel art stays crisp); everything else high. Click events report canvas-local, y-down coordinates.

Error card / placeholder

Honest and directive, never mood: name the phase (no host · no apps · starting) and the exact command that fixes it (cd host && bun run start). Errors don't apologize; empty states say what to do next. This is the voice for all system copy.

D7

The laws

The checklist for the cleanup agents — and for every component that comes after. Each law exists because we shipped its violation.

L1

One ruler. Every color from LedgeTheme, every metric from LedgeMetrics (new). An inline literal in a component is a defect even when the value is correct.

L2

Centering is measured, never trusted. NSTextField/NSButton cell metrics lie; measure the string and center the content group yourself. Empty content contributes zero width and zero gap.

L3

Radii come from the two rules. Controls are capsules; nested containers are concentric (parent − inset, floor 4). All corners .continuous.

L4

Press scales about the visual center (setPressScale — layer anchor is (0,0), compensate). 0.96 labeled / 0.92 icon, 80 ms in, 120 ms out.

L5

Hover is verified against the live pointer (syncHover + NSEvent.mouseLocation). Tracking areas go stale whenever the panel morphs under a stationary cursor.

L6

State changes animate; layout ticks don't. Hover washes ease 120 ms; drag ticks, chart updates, and corner changes run under CATransaction.setDisableActions.

L7

Text never wraps silently. One line, tail truncation, measured intrinsic width (+6). Multi-line is opt-in via maxLines — implement the §5 truncate prop while in there.

L8

One white. Ink is white at .94/.56/.32; washes at .055/.085/.09/.14. No new grays, no new alphas without a token and a reason.

L9

Hue is meaning. Apps name intent (accent, greenTint…); the shell owns values. One hue family per card; accent once per panel.

L10

Draw against bounds, never dirtyRect. The halo bug's law. Layer backgrounds preferred over draw(_:) where possible.
