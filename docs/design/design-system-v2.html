Ledge · Design System v2

The target design for a Mac-native app platform that happens to live around the notch. This document deliberately separates shipped, platform proposal, and showcase concept. Unmarked token values are transcribed from Theme.swift / Metrics.swift; proposed contracts are decisions for the next host and protocol revision, not descriptions of the current build.

1 · Color

One dark theme. Whites at fixed alphas do all structural work; color is reserved for meaning (status, accent, agent). Every accent carries a derived tint (8–10% fill) and stroke (20–25% border) so tinted chips look related by construction.

4 · Surfaces — ownership, not a ladder

The surfaces have different owners. The active app owns the wings and panel; any running app may publish a bounded mini notification; the builder owns chat. A mini is an event overlay, not a smaller panel state, so it can arrive without stealing selection, lifecycle, wings, or the app the pill reopens. platform proposal

4.1 Collapsed pill + wings

The pill is anchored to the hardware cutout (never centered — wings are asymmetric). Fillet 12, bottom radius 12. Left wing: text, 11.5 semibold secondary, max 160 pt. Right wing: a chromeless canvas — it is the pill. Wings are decoration: hit-tests pass through. Hover: haptic + bump (+14 w, +2.5 h), open after 0.20 s dwell; click opens instantly. Only the active app's latest wing declaration is visible; background declarations may be retained for the next activation but never replace the current app's wing. ownership change

4.2 Mini — a background-capable notification

Mini is a separate React root exported by each app, not an element nested inside its panel. When Ledge is collapsed it morphs out of the pill; when another app's panel is open it attaches below that panel as a prominent notch-shaped toast. It never changes the active app. Height 34–80, default duration 4 s; hovering pauses dismissal and clicking may perform the notification action or activate its source app.

4.3 Mini authoring contract platform proposal

Mini owns presentation and hooks; ctx.peek supplies an ephemeral, JSON-safe event and asks the shell to show it. Shared app state continues to arrive through the normal update path, so panel and mini can render the same model without sharing a React tree. The shell mounts one independent mini root per running app and disposes the event payload after dismissal.

export default function App({ track }) { /* panel */ }

export function Mini({ track, event, onOpen }) {
  return <row><text>{event.title}</text><button onClick={onOpen}>Open</button></row>
}

ctx.update({ track: next, onOpen: () => ctx.expand() })
await ctx.peek(
  { key: "track-changed", title: next.title },
  { duration: 4000, prominence: "normal" }
)

the JSX never crosses the socket · payload must be JSON-safe · callbacks are declared in the mini tree · background peek does not emit visible/hidden or change active app

5 · Frosted controls platform proposal

Controls use one translucent, softly textured frost over the app's content. Every button, segmented control, stepper, slider thumb, toggle, and field shares the same blur, neutral white veil, fine grain, edge ring, and shadow. There is no simulated lens, travelling highlight, refraction, or merging behavior. That restraint makes the animated content underneath visible without making the controls look wet or unstable.

The material changes only by state: hover raises opacity and shadow slightly, press scales the complete control to .96, selection adds a quiet inner wash, and the single primary action receives an accent tint over the same frost. Native implementation should use one shared NSVisualEffectView-backed material; Reduce Transparency substitutes an opaque neutral with the same ring and metrics.

Legibility over generative content is a mechanism, not an aspiration. "Controls remain readable over every generated frame" cannot be left to the app — a performance that drifts pale will eat the transport. Two rules, deliberately deterministic rather than adaptive: the frost carries a contrast floor (a veil component tuned so worst case — full white behind — still clears the ink), and a scene declares a quiet band the generative grammar must keep below a luminance and detail cap. Sampling the scene per frame and adjusting the veil is the obvious alternative and it is wrong here: an adaptive scrim shimmers as content moves, which is exactly the wet, unstable look the frost exists to avoid. platform proposal

7 · Settings — a native window proposed

Settings stops being an app in the strip and becomes a real macOS window. The decisive argument isn't taste, it's architecture: an app's settings must be editable while that app is disabled or has never started, so the schema has to live in the catalog the host already owns — not in a running worker's React tree. It also deletes a whole special case: the privileged bridge exists mostly so one app could enable/disable the others, and the shell already owns that state.

An app declares meta.settings. It must be plain JSON, not Zod — the renderer lives in another process, so the schema crosses a socket; a Zod schema is closures and can't. Types map to real AppKit controls, so a Ledge app's preferences look like every other Mac app's.

Where the values live and how they get back. The shell owns them (it draws the UI and outlives every worker), persisted per app beside the existing settings.json — which today holds exactly one key, the disabled list. They reach the worker as a frozen ctx.settings at boot and as an app-level event on change, so both monitor() and the component see the same object. Apps that need to react to a change export onSettings(values, ctx); everything else just re-renders.

consequences: the Settings demo app is deleted · the strip gear opens this window · ctx.permissions() becomes "open this window at Permissions" · reorder (never implemented) becomes drag-to-reorder in the sidebar · secrets never enter settings.json or logs

8 · Cadence & animation

There are three clocks in Ledge and conflating them is the main way apps go wrong. The monitor is not an animation clock — it's a data loop with a 1 s spin floor, and every app that animates today already bypasses it entirely: monitor() captures ctx, does its setup, then parks on await new Promise(() => {}) while a plain setInterval owns the frame clock. That's the shipped pattern, not a workaround.

ClockRateCost per tickUse for
Monitor loop≥ 1 s (spin floor, not an interval) whatever your poll costsfetching data. never motion.
ctx.draw + own intervalapp-chosen; 60 Hz is the hard ceiling JSON encode → socket → 3 JSON passes in Swift → rasterpixels: scenes, games, charts
rate prop30 Hz, shell-sidezero — no wire traffic at all one predictably-moving number
React commitevent-driven only reconcile + validate + relayout — milliseconds never for animation

Why 60 Hz is a ceiling and not a target. The shell coalesces draw frames per canvas and flushes on a 60 Hz timer, so a 120 fps app pays full JSON-encode, socket, and decode cost for frames that are discarded before they are ever drawn. Worse, coalescing happens on the receiving side — there is no backpressure anywhere in the chain, and the host's outbound queue is unbounded. Drawing faster than the screen is pure waste that the platform cannot currently refuse.

The house numbers: 15 fps for ambient scenes (the shipped default — weather, flocks), up to 30 fps for anything with a cursor following it, 60 Hz only for a game that earns it. And the non-negotiable: hidden surfaces don't animate. The panel canvas stops when closed, inactive mini roots are event-driven, and a visible bounded mini may animate only for its on-screen lifetime. The active app's wing may keep moving at around 2 fps.

Op budget — the generative scene is the first thing that strains this. Frame rate was never the constraint; frame size is. Today's heaviest app, a full Tetris well, is ~120 ops ≈ 8.5 KB. A per-particle performance is a different order: 1,000 particles ≈ 60 KB a frame, and at 15 fps that's ~900 KB/s of JSON — encoded in Bun and then decoded three times in Swift, because decodePayload re-encodes before it re-decodes. That bug is a nitpick at Tetris scale and a real cost here.

Three answers, in order of preference. Choose grammars with few rich ops rather than many poor ones — forty flowing paths of fifty points each say more than a thousand loose particles and cost a third as much; this is a design constraint before it is an engineering one. Quantize coordinates — the canvas is 200–440 pt wide, so sub-half-pixel precision is invisible and integers cut a points array roughly in half. And if a grammar genuinely needs thousands of primitives per frame, that is the first honest case for the stubbed "use native" transducer — the one the earlier verdict said not to build, because Tetris and aviary never justified it. platform proposal

verdict on a new meta knob: not needed for capability — apps can already animate at any rate. what's missing is a cap: a declared meta.canvas.fps the shell may enforce, so a runaway app degrades visibly instead of silently eating a core. two adjacent bugs found while checking: decodePayload re-encodes then re-decodes every draw frame (3 JSON passes where 1 would do), and the hidden/visible lifecycle phases are specified but never actually sent.

9 · Platform contract v0.4 platform proposal

The platform should let Codex author an app as a small durable program with four independent responsibilities: observe, decide, present, and notify. A panel-only React demo proves rendering; these contracts prove that Ledge can host useful software that keeps working after the user switches away.

panel root
Default export. The selected app's full interactive view; mounted only when needed and never treated as a background process.
mini root
Named Mini export. Independently reconciled for every running app and shown only after ctx.peek(event, options).
background
monitor(ctx). Continues under explicit cadence and energy budgets when another app is active; the shell can suspend it and reports the lifecycle honestly.
wings
Active app only. Each app retains its latest declaration, but the shell renders the declaration belonging to the selected app and restores it after a mini.
notification queue
Shell-owned arbitration. One visible, three queued, coalesced by app + key, rate-limited per app, hover-paused, and accessible through a notification history.
scene canvas v2
Generative work without sprite packs. Add paths, circles/ellipses, linear and radial gradients, transforms, alpha, clip, and blend modes in atomic frames; keep high-rate React commits out of animation.
permissions
Capability-scoped and revocable. Location, Calendar, Photos, and user-selected folders are separate grants; apps declare why before the native prompt and render a useful limited mode after denial.
secrets
Keychain-backed settings. API keys are never ordinary props, JSON files, chat context, crash reports, or generated source literals.

Mini and wings stay separate for v0.4. A mini already supplies bounded transient attention, so allowing background apps to borrow the wings adds arbitration and restoration rules without unlocking a new user outcome. Revisit only if a real showcase needs a notification that cannot fit 34–80 pt.

10 · Codex-authored demos recorded / live only

These are demonstrations of Codex targeting the platform, not bundled AI products. The impressive act is turning one person's peculiar need into ordinary inspectable software, then leaving that software running. Avoid purple assistant chrome, fake autonomous commentary, and generic chat panels; show the source, the hot reload, the useful state, and the later background mini.

make it observable
Point Codex at any command, JSON endpoint, log, or page. It builds a wing for the one ambient value, a panel for history, and a keyed mini for the condition the user describes. Swap the source between recordings to prove it is a platform pattern, not a prebuilt monitor.
make it controllable
Give Codex a local script, device API, or repetitive command. It turns safe operations into a tactile control surface with status, confirmation for risky actions, and receipts. The before/after is visible in the real system, so the demo doesn't depend on prose.
teach a standing order
Perform one file task, then say “always do that for these.” Codex adds a Shelf container, matcher, preview, transform chain, failure state, and undo; the next real file travels through it while another app is active.
build my odd instrument
Combine facts no product team would prioritize. “Tell me when direct sun reaches my desk” can join window orientation, local solar geometry, and cloud cover into a tiny instrument with a live shadow diagram and a future mini. Specificity is the proof.

Every recording has the same five beats: a concrete desire, one real source inspected, code written in view, hot reload into all relevant surfaces, then a time jump showing the monitor delivering a mini while a different app is active. A second natural-language change proves the app remains editable. CI Medic is removed because repository triage is already a familiar agent demo and says little about why this platform belongs around the notch.

11 · Laws

Product laws explain what the system should feel like. Engineering laws keep that feeling from decaying in implementation. Both are review criteria; status labels still decide what is shipped.

Product laws

  1. Useful before delightful. Every flagship performs a recurring job; its surprise makes the job worth revisiting rather than disguising the absence of one.
  2. Delight compounds. Sessions leave history, mastery, a landscape, a rule, or a changed model. A reset-to-zero spectacle is a demo, not a relationship.
  3. One signature per app. Name the one device people will describe to a friend; controls and supporting content stay quiet enough to frame it.
  4. Frost controls, content lives. A uniform translucent control material sits over expressive content. Cards and backgrounds stay quieter, so hierarchy survives the effect.
  5. Background events don't steal foreground state. A mini may interrupt visually for a bounded moment, but it never changes selection, wings, lifecycle, or reopen history.
  6. Time remains calm. Ambient surfaces use human units and show available action. Seconds belong to user-controlled clocks and games, not unavoidable countdown anxiety.
  7. Permission is part of the experience. Ask at the moment of value, scope the grant, explain the local index, provide a useful denied state, and make deletion obvious.
  8. Empty states invite. One glyph, one sentence, one action — never an apology and never “no data.”

Engineering laws preserved from v1

  1. One ruler. Every color comes from LedgeTheme and every metric from LedgeMetrics. An inline component literal is a defect even when its value is correct.
  2. Centering is measured, never trusted. AppKit cell metrics lie; measure strings and center the complete content group. Empty content contributes zero width and zero gap.
  3. Radii come from two rules. Controls are continuous capsules; nested containers are concentric, using parent radius minus inset with a floor of 4.
  4. Press scales about the visual center. Compensate the layer anchor; use .96 for every control, 80 ms in and 120 ms out.
  5. Hover is verified against the live pointer. Tracking areas become stale when the panel morphs beneath a stationary cursor; resync from NSEvent.mouseLocation.
  6. State changes animate; layout ticks don't. Hover washes ease over 120 ms; drag ticks, chart updates, and corner changes disable implicit Core Animation actions.
  7. Text never wraps silently. Default to one line with tail truncation and measured intrinsic width; multiline is explicit through maxLines.
  8. One white. Ink and structural whites use named alpha tokens. A new gray or alpha needs a token and a semantic reason.
  9. Hue is meaning. Apps name intent, the shell owns values, each card uses one hue family, and a filled accent appears once per panel.
  10. Draw against bounds, never dirtyRect. Prefer layer backgrounds where possible; partial invalidation must never alter geometry or leave a halo.
  11. Know which clock you're on. Data polls through the monitor, pixels use ctx.draw, and one predictable number may use rate. React commits never drive continuous motion.
  12. Hidden surfaces are idle. Stop panel animation when closed and mini animation after dismissal; only the active wing has a low-rate collapsed budget.
